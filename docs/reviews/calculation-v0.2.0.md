# v0.2.0 计算方式复核

核验日期：2026-09-05。结论：**既定模型的核心积分和倍率通过独立数学交叉验证，但绝对游戏产量仍有未完成实测的假设。** 本次发布不宣称所有数值与当前游戏版本完全一致，也不保证全局最优排班。

## 独立数学验证

`tests/calculation-oracle.test.mjs` 不复用模型常量或生产倍率函数作为期望值，新增 8 项检查：

| 场景 | 独立期望 |
| --- | --- |
| 单人无技能自动循环 | 工作 `100/7` 小时，休息 `100/12` 小时，完整周期在岗率 `12/19`，平均倍率 `1.4 × 12/19` |
| 三人同轴且各减耗 10%、匹配增产 20% | 消耗率 `7 × 0.7`，在岗倍率 `2.2 × 1.6`；其他配方技能不计入 |
| 三人错峰 `0 / 2.5 / 7h` | 独立构造各人的周期工作区间，按区间交点积分；对照 60 日预热、30 日采样 |
| 总控与生产同步上下班 | 总控休息时恢复加成消失；不能将总控技能永久施加于整个周期 |
| 两组各工作 12 小时 | 休息充分，三名各 10% 增产干员保持 `2.86` 倍率 |
| 一组工作 12 小时后换成空组 | 覆盖率 `0.5`、日停产 12 小时、平均倍率 `0.7` |
| 定向线索 | L1/L2 不增加线索总数 |
| 全部空设施 | 各资源产量为零、基础恢复为 12 |

上述数值比较误差要求小于 `1e-8`。这验证的是计算实现与数学模型一致，不将模型假设自动视作游戏事实。

## 本轮补充修复

- 固定换班候选筛选原先预热 45 日，展示预热 60 日。改为共同使用模拟器默认的 60 日预热、30 日采样，避免因窗口不同而选择与最终显示口径不一致的方案。
- 制造舱独立配方测试曾将同一组 ID 放进两个设施，后一个设施被去重为空而仍通过零值等式。改用独立 ID，并要求两种产物均大于零。
- 上一轮修复的跨设施技能切换、心情继承、时间与班次索引绑定继续纳入完整回归。

## 数据来源与仍需实测的口径

[终末地 BWIKI 总控中枢资料](https://wiki.biligame.com/zmd/%E6%80%BB%E6%8E%A7%E4%B8%AD%E6%9E%A2)（页面标记更新于 2026-02-03，本轮访问于 2026-09-05）记载了基础心情恢复/消耗、进驻加成与技能乘算、制造耗时和培养箱数量。这是社区整理资料，页面本身提示数据可能缺失或不准确。

| 项目 | 当前实现及核验边界 |
| --- | --- |
| 心情与进驻倍率 | 7%/小时消耗、12%/小时恢复、每人 40% 进驻加成后乘匹配技能；与上述资料及项目既定口径一致 |
| 制造 | 使用既有 `24:26:40` / `09:46:40` 做单份等效时长，不将载荷 480 直接作为并行倍率，也不额外乘每批数量。公开表格未充分说明该时长的基础效率与批次数量，仍需用当前游戏内生产任务实测对照 |
| 培养 | 类别用于选择技能；数值统一按 9 箱、每箱 `61:06:40` 估算。资料还列有 `125:00:00` 等耗时，同类别不等于同耗时，因此这些材料不能直接套用当前数量结果 |
| 线索 | 延续 72 小时基础搜集周期，但本轮未找到足以独立证实此常量的可靠依据。情报交流持续时间与线索搜集周期不同，不能相互替换 |
| 无人在岗 | 延续用户确认的停产模型。未模拟无人生产、收获延迟、载荷队列、助力或手动补心情 |
| 求解 | 人员组合为启发式候选加模拟筛选，挂机半小时网格搜索使用长窗口复核；不是所有人员与启动轴组合的全局穷举，也不是无限期收益的数学证明 |

已在“关于”、培养/线索指标说明及双语 README 明确主要估算口径。后续若获得游戏内基准任务的每批数量、起始效率和完成时间，应同步修改常量、单位转换、界面说明及独立测试，不能只调整显示数字。
