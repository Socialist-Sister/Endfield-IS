# 计算性能复核 · 2026-09-06

用户反馈计算变慢，并要求恢复“已选 N/30”方框。此次工作区更新优化挂机计算热路径，同时恢复计数控件的 1px 方角边框。此前的视觉调整没有修改计算引擎；未发现搜索参数被提高或模拟范围发生变化。

## 定位与改动

CPU 采样显示主要耗时位于 `simulateAfkModel`。将事件循环内反复创建的数组回调改为顺序循环，保留事件更新、心情阈值与浮点运算顺序。

新增 `axisEvaluationCache.js`：只有干员在每个受影响设施中的产量、减耗与恢复效果完全相同时，才复用交换这些干员启动时间后的评估。统一轴同时检查总控；分设施局部搜索的总控启动轴固定。初筛与最终验证各自拥有缓存，不跨输入、搜索阶段或模拟窗口复用。第三槽位之外干员沿用最后偏移的边界也已考虑。

全部候选和排序决胜规则保留，30 分钟分辨率、初筛 30 天预热 / 15 天采样、最终 180 天预热 / 90 天采样、分设施与统一轴基线的最终比较均保持不变。

## 本机同配置对照

全员 E4、默认配方、矿物质料。使用同一进程交替运行优化前后引擎各两轮，关闭 CPU 采样，比较 `buildDailySummary` 耗时；不包含浏览器加载、分配和结果切页动画。

| 模式 | 优化前平均 | 优化后平均 | 耗时降低 |
|---|---:|---:|---:|
| 统一启动轴 | 2.656 秒 | 1.108 秒 | 58.3% |
| 分设施启动轴 | 9.114 秒 | 3.184 秒 | 65.1% |

浏览器实际点击至结果显示：统一轴 1.367 秒、分设施轴 4.172 秒（包含 Worker 启动及界面完成过渡）。不同机器、后台负载、干员和练度组合会影响耗时；没有等效干员槽位的组合主要受益于循环优化。

原始对照记录位于已忽略的 `.audit/paired-performance.json`，常规基准仍使用 `npm run benchmark`。

## 正确性与界面验收

- 100 组随机模拟与优化前引擎深度相等，含不同技能、空队伍、额外成员、启动时间和模拟窗口。
- 4 组完整搜索（同技能 / 不同技能，统一 / 分设施）与旧引擎深度相等；默认完整阵容的前后基准 summary 也逐项相同。
- 新增 7 项缓存边界测试，涵盖不同产量、减耗、恢复效果、跨房间总控差异、阶段隔离、输入不变及额外成员。
- 全部 80 项测试、生产构建、Sites 4 项与差异格式检查通过。
- 浏览器确认“已选 30/30”恢复 1px 方角边框，高度 40px，与工具栏其他控件一致。配置预览同步更新。
